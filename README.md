## О проекте

English Step — приложение для самостоятельного прохождения курса «Английский язык за 20 уроков». Каждый урок содержит ссылку на видео, правила, примеры, типичные ошибки и проверочный тест. Русскоязычный интерфейс показывает состояние уроков, результаты попыток и общий прогресс.

Приложение работает без регистрации. Оно рассчитано на **одного общего учащегося**: каноническое состояние хранится в Supabase, а браузер держит кэш и очередь операций для временных сетевых сбоев. Это не система раздельных персональных аккаунтов.

## Возможности

| Раздел | Что реализовано |
| --- | --- |
| Уроки | 20 тем уровня A2, встроенные YouTube-видео и переход на YouTube, правила, примеры и тесты |
| Тесты | 181 вопрос в данных курса; разные типы заданий, проверка ответов и объяснение ошибок |
| Последовательный режим | Следующий урок открывается после просмотра видео и результата не ниже 70% за предыдущий тест |
| Ежедневная практика | Тесты по каждому уроку и отдельный набор из шести вопросов дня с серией дней |
| Прогресс | Просмотренные видео, попытки, последний и лучший результат, правильные ответы, серия и сброс с подтверждением |
| Интерфейс | Светлая и тёмная темы, адаптивная навигация и поддержка настройки уменьшения движения |

Контент уроков находится в [`src/data/`](src/data). В исходных данных 20 уроков, по 9–10 вопросов на урок; интерактивные проверки реализованы в [`Quiz.tsx`](src/components/Quiz.tsx) и [`DailyGame.tsx`](src/components/DailyGame.tsx).

## Хранение прогресса и работа без сети

[`src/lib/progress.ts`](src/lib/progress.ts) читает снимок прогресса через Supabase RPC и записывает изменения как операции с уникальным ID. Операции включают отметку о просмотре, результат теста, последовательный режим, дневное задание и сброс. База применяет их атомарно и идемпотентно; история попыток хранится отдельно в `quiz_attempts`.

Когда сеть недоступна, приложение показывает локальный кэш и сохраняет ещё не отправленные операции в `localStorage`. При возвращении фокуса, соединения или открытии вкладки оно повторно загружает серверное состояние и отправляет очередь. Доступность контента YouTube при этом зависит от YouTube и сети: офлайн-воспроизведение видео не реализовано. Текущая попытка «Вопросов дня» дополнительно сохраняется в cookie браузера.

> [!IMPORTANT]
> В приложении нет входа и разделения учащихся. Publishable key доступен браузеру, а все посетители с доступом к сайту работают с одним профилем `primary`. Политики базы ограничивают прямые записи; проверенные RPC принимают изменения прогресса. Ссылку на рабочий экземпляр следует считать доступом к общей учебной истории.

## Устройство проекта

```text
src/data/               Данные 20 уроков, видео и вопросов
src/routes/             Главная, уроки, ежедневная практика, прогресс, о курсе
src/components/         Тесты, видео, навигация и виджеты прогресса
src/lib/progress.ts      Кэш, очередь операций и синхронизация с Supabase
supabase/migrations/     Таблицы, ограничения, RLS и RPC прогресса
docs/                   Исследовательские заметки по данным и развёртыванию
```

Frontend построен на React 19, TypeScript, TanStack Start/Router, Vite и Tailwind CSS 4. Доступ к данным выполняет Supabase JS. Для форм и интерфейса используются React Hook Form, Zod и Radix UI.

## Локальная разработка

Репозиторий содержит `bun.lock`; для команд ниже нужен Bun. Подключение к прогрессу требует настроенного Supabase-проекта с [миграциями](supabase/migrations):

```bash
git clone https://github.com/Yozekkk/nelli-english.git
cd nelli-english
bun install --frozen-lockfile
cp .env.example .env.local
bun run dev
```

В `.env.local` задайте `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY` для своего проекта. Имена переменных приведены в [.env.example](.env.example). Эти значения доступны браузеру; не помещайте в `VITE_*` сервисные ключи, пароли или токены. Без корректного Supabase прогресс не синхронизируется.

## Проверка и сборка

В [package.json](package.json) определены следующие команды:

```bash
bun run test
bun run lint
bun run build
bun run preview
```

`test` запускает Bun tests с временной зоной `Europe/Budapest`; `preview` просматривает локальную production-сборку. Отдельного `typecheck` script и GitHub Actions workflow в репозитории нет. Production-конфигурация Vite выбирает Nitro preset для Vercel при наличии `VERCEL`; без него используется стандартная конфигурация проекта. Состояние конкретного deployment следует проверять отдельно.
